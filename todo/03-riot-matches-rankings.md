# Riot 계정·전적·학교 랭킹

## 외부 연동 원칙

API 호출은 `Endpoint → Application → Riot 서비스 → 캐시 → Riot HTTP Client`로 통합한다. PUUID를 플레이어 식별자로 사용하고 Riot ID의 gameName/tagLine은 갱신 가능한 표시값으로 취급한다. KR 시작안은 플랫폼 호출과 지역 호출을 분리한다. 현재 API별 경로·버전은 구현 시 [Riot API Reference](https://developer.riotgames.com/apis)에서 다시 확인한다.

| 데이터 | 공식 API 계열 | KR 시작안 |
| --- | --- | --- |
| Riot ID ↔ PUUID | Account | 지역 라우팅 `asia` |
| 레벨·프로필 아이콘 | Summoner | 플랫폼 라우팅 `kr` |
| Solo/Flex 랭크·승패 | League | 플랫폼 라우팅 `kr`, 지원되는 PUUID 경로 우선 |
| 경기 목록·상세 | Match | 지역 라우팅 `asia` |
| 숙련도 | Champion Mastery | 플랫폼 라우팅 `kr` |
| 챔피언·아이템·룬·스펠·아이콘 | Data Dragon | 버전·언어별 정적 데이터 |

라우팅·식별자 근거: [Riot LoL 개발 문서](https://developer.riotgames.com/docs/lol#routing-values). `KR1` 같은 tagLine을 지역 선택 값으로 사용하지 않는다.

## 초기 캐시 값 제안

실측 전 출발점일 뿐 외부 API 보장값이 아니다. Account 6시간, 랭크/최근 경기 목록 5분, 숙련도 1시간, 학교 랭킹 5분, 수동 갱신 쿨다운 1분을 설정값으로 둔다. 완료 경기 상세는 DB에 저장하되 보존 정책과 수정/스키마 버전 재수집을 고려한다. 정적 데이터는 패치 버전별로 장기 캐시한다.

## LCG API 초안

- `PUT/DELETE /api/v1/me/riot-account`
- `GET /api/v1/players/search?gameName=...&tagLine=...&platform=kr`
- `GET /api/v1/players/{playerId}` 및 `/matches`, `/masteries`
- `POST /api/v1/players/{playerId}/refresh`, `GET /api/v1/sync-jobs/{jobId}`
- `GET /api/v1/matches/{matchId}`
- `GET /api/v1/rankings?queue=solo|flex&grade=...&position=...`, `GET /api/v1/rankings/me`

`playerId`는 내부 플레이어 ID다. PUUID와 저장소 접근 권한을 혼동하지 않는다. 조회 권한·페이지 상한·공개 필드 정책은 공통 계약을 따른다.

## 공식 문서에 따른 외부 제약

개발 키는 24시간 만료되며 공개 서비스용이 아니다. Personal 키의 소규모 비공개 이용 범위와 공개 alpha/beta 제한을 확인한 뒤 적절한 운영 키를 사용한다. 429 응답에는 호출 중단 및 제한 해제 시점 처리가 필요하다. [키·오류·제한 문서](https://developer.riotgames.com/docs/portal)

RSO는 Production 수준 접근이 필요하다. 커스텀 경기 공개는 참가자의 명시적 공개 동의 조건을 확인해야 하므로 일반 전적과 별도 경로로 다룬다. [RSO 및 LoL 정책](https://developer.riotgames.com/docs/lol#rso-integration)
